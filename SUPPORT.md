# How to get help

**[Open an issue / Abrir un issue](https://github.com/issacbrizuela1/PUB-P-APP-ROUTEHOUND/issues/new/choose)**

*[Versión en español abajo](#espanol). Same text as in the app (About).*

Support and contact go through the issues of the public repository `github.com/issacbrizuela1/PUB-P-APP-ROUTEHOUND`. You need a GitHub account.

## Before you open an issue

- Search the open and closed issues: it may already be solved.
- Update to the latest version (About › Check for updates).

## When you open an issue

- One problem or question per issue.
- Use the template: **Report a problem** for bugs and **Ask a question** for questions or ideas.
- Include the version, the operating system, the steps to reproduce it, what you expected and what happened. Opening it from the app (About › Support) fills in the version and the system.
- If you can, attach a screenshot or a minimal sample project.

## What you must never post

Issues are **public**. Never paste tokens, passwords, API keys, personal data or private code. Replace them with `***` or sample data.

## Security vulnerabilities

Do not post them in an issue. Use "Report a vulnerability" in the repository's Security tab, which is private.

## Replies

Routehound is maintained by one person: replies are best effort, with no guaranteed time. Issues without the needed information, or inactive ones, may be closed.

# Cómo pedir ayuda

El soporte y el contacto se hacen por los issues del repositorio público `github.com/issacbrizuela1/PUB-P-APP-ROUTEHOUND`. Necesitas una cuenta de GitHub.

## Antes de abrir un issue

- Busca entre los issues abiertos y cerrados: quizá ya está resuelto.
- Actualiza a la última versión (Acerca de › Buscar actualizaciones).

## Al abrir un issue

- Un problema o pregunta por issue.
- Usa la plantilla: **Reportar un problema** para fallos y **Hacer una pregunta** para dudas o ideas.
- Indica la versión, el sistema operativo, los pasos para reproducirlo, lo que esperabas y lo que pasó. Si lo abres desde la app (Acerca de › Soporte), la versión y el sistema ya vienen puestos.
- Si es posible, adjunta una captura o un proyecto de ejemplo mínimo.

## Lo que nunca debes publicar

Los issues son **públicos**. Nunca pegues tokens, contraseñas, claves de API, datos personales ni código privado. Sustitúyelos por `***` o por datos de ejemplo.

## Vulnerabilidades de seguridad

No las publiques en un issue. Usa "Report a vulnerability" en la pestaña Security del repositorio, que es privado.

## Respuestas

Routehound lo mantiene una sola persona: las respuestas son de mejor esfuerzo y sin plazo garantizado. Los issues sin la información necesaria o inactivos pueden cerrarse.
